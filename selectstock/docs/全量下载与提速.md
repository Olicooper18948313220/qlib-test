# 全量下载与提速

更新日期：2026-11-03（Australia/Sydney）。本次保持所有合格股票的历史下载任务，不先按市值或扫描入选情况缩小日线股票池。已有数据库与历史均保留。Leader 和 Potent 独立使用同一份日线，不需要分别下载行情。

## 扫描需要多长历史

下面的长度由当前规则和实现推算，不是 Martin Luk 公开指定的下载长度。

| 扫描器 | 计算所需数据 | 实际运行建议 |
| --- | --- | --- |
| Leader | 10 个交易日日均量、本周累计行情、30 个自然日前或更早的月表现锚点 | 日线 45–60 个自然日，留出休市及锚点余量 |
| Potent | EMA50 至少 50 个交易日才能按本项目 SMA 初值生成数值；另需最近 7 个自然日振幅和前日收盘 | 当前程序要求至少 250 个交易日，以减少 EMA 初始化影响；全年下载建议先保留 365 个自然日，并检查实际条数 |

EMA 使用前一日 EMA 递推，所以“能生成 EMA50”不等于“与更长历史计算完全一致”。150–200 个交易日可作为另行评估的折中方案，接近筛选边界时仍可能影响名单；当前版本没有下调 250 条保护。EMA 公式：https://www.tradingview.com/support/solutions/43000592270-exponential-moving-average/ 。

`HISTORY_DAYS["1d"]` 是请求的自然日范围，`READ_BARS` 是扫描读取条数。扫描器会自动将读取量提高至预热要求；改小 READ_BARS 不能绕过 250 条保护。365 个自然日通常约有 250 个交易日，上市时间短、停牌或缺数据的股票可能不足，需看诊断结果。

从两年缩到一年会减少响应体、存储与计算量，但通常每只股票仍要一次历史请求，不能据此将总耗时直接减半。在当前保留一年历史的设置下，优先减少重复资料请求。

## 已实现的提速

- 资料批量获取：交易所查询不设市值下限，每页至多 250 个报价，与本地完整股票池匹配。
- 复用报价返回的时区，减少每只股票首次查询时区的请求。
- 资料失败记录等待时间；批量遗漏限制逐股补查数量，避免少数异常代码消耗大量预算。
- 上市前日期明确标记；完整行情仍命中本地缓存，缺失区间可续传。
- 共享限速改为请求起始间隔 1–1.2 秒，每 100 次额外休息 10 秒。每轮 600 次、429/403 冷却、连续错误保护均保留。

增加 `batch_size` 只改变本地循环批次，不会增加并发或合并 Yahoo 历史请求。免费源没有固定安全配额，提速后仍须遵守服务端冷却。

## 本机实测与耗时估计

这是提速验证，不是全量历史下载完成报告：

| 项目 | 结果 |
| --- | --- |
| 当前股票目录 | 5,898 个合格代码 |
| 一次全市场批量资料刷新 | 31 次 Yahoo Session 请求，约 40 秒；本轮保存 5,717 条，连同已有资料共 5,836 个代码有有效市值 |
| 尚缺有效市值 | 62 个代码；保留历史下载，扫描标记无法判断 |
| 20 个此前无日线的代码，365 个自然日 | 22.7 秒，21 次请求，4,680 条日线；行情与资料失败列表为空 |
| 重复更新上述 20 个代码 | 全部命中缓存，新增 0 条，网络请求 0 次 |

按 20 支样本推算，首次全市场一年日线约 2–4 小时，包含正常分组等待与请求预算暂停，不包含手动续传延迟和额外限流冷却；异常股票、网络变慢和数据修复可能延长。尚未完成全市场计时验证，不承诺上述时长。新股历史不足一年，因此 4,680 条不意味着样本缺口。

## Notebook 01 操作

1. 若旧更新单元格仍在运行，点击停止，等待其结束。点击顶部 Restart 重启内核，使新代码生效。
2. 从第一格导入开始运行。在集中参数格确认下面设置，再执行该格。其余构造 config 的代码保留。

```python
DEMO = False
SYMBOLS = []
WATCHLIST = []
HISTORY_DAYS = {"1d": 365, "15m": 30, "5m": 30, "1m": 7}
READ_BARS = 252
END = None
LEADER_ENABLED = True
POTENT_ENABLED = True
RUN_DAILY_UPDATE = True
RUN_INTRADAY_UPDATE = False
DISPLAY_SYMBOL = "AAPL"
```

3. 运行数据库检查格，再运行注释为“单独更新日线”的代码格。初次先批量刷新缺失资料，再补日线。无需删除数据库或使用 repair。
4. 若报告 `paused=True`，看 `pause_reason` 与 `resume_after`。普通请求预算用完最少等待 60 秒；限流按报告等待至少 15 分钟。之后仅重跑日线更新格，从已保存进度继续。不要点击整本 Run All 触发不必要的后续步骤。
5. 重复直到一整轮未暂停且所有代码被处理。完成后改 `RUN_DAILY_UPDATE=False`，重新执行参数格，再分别执行 Leader、Potent 与导出格。是否“全量跑通”还应核对 failures、metadata_failures 和扫描覆盖率，不能只看 downloaded 数量。

分钟更新保持关闭。WATCHLIST 是额外维护分钟线的自选股列表；留空不会缩小日线股票池。全量日线完成后，另行下载扫描入选股与 WATCHLIST 的分钟数据。
