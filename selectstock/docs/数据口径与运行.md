# 数据口径与运行

## 本地数据流

Nasdaq 目录 → 股票资料快照与日线同步 → SQLite → 单股限定窗口 → 指标 → Leader/Potent → 诊断、CSV 和 TXT。分钟线另按启用扫描器最近成功名单与自选股的并集同步。最新空名单会替换该扫描器先前名单；停用的扫描器不提供下载候选。旧分钟历史保留，但不持续维护离开候选池的代码。

Nasdaq 数据：`nasdaqlisted.txt` 和 `otherlisted.txt`，https://www.nasdaqtrader.com/Trader.aspx?id=SymbolDirDefs 。按交易所、ETF/Test/NextShares 标记、证券名称及符号过滤权证、优先股等。目录没有完全规范化的普通股分类字段，名称过滤不能保证识别所有特殊证券。保留 ADR，当前目录存在幸存者偏差，不宣称完整历史股票池。

Yahoo/yfinance： https://ranaroussi.github.io/yfinance/reference/api/yfinance.download.html 。免费服务可能限流或延迟。同步按股票顺序处理。瞬时错误最多尝试 3 次，退避 5、10 秒加小幅随机等待；参数/数据校验错误不重复请求，429/403 触发整轮暂停。

## 下载频率与暂停

所有项目创建的 Yahoo Session 请求（包括 yfinance 内部的行情、资料、cookie 调用及内部重试）经过共享保护器。它在整个请求期间持有跨进程文件锁，同项目两个 Notebook 不会形成并发请求流。

| 配置 | 默认值 | 含义 |
| --- | ---: | --- |
| request_pause_seconds | 1.5 | Yahoo Session 请求起始时间最小间隔，秒 |
| request_jitter_seconds | 0.5 | 每次额外等待 0–0.5 秒 |
| download_batch_requests | 50 | 每组请求数量 |
| download_batch_pause_seconds | 15 | 每组之后额外休息秒数 |
| max_requests_per_run | 600 | 单轮 Yahoo Session 请求预算，非股票数量 |
| budget_cooldown_seconds | 60 | 预算用尽后再次运行前最少等待 |
| rate_limit_cooldown_seconds | 900 | HTTP 429/403 或明确限流异常后的最小冷却 |
| max_consecutive_failures | 5 | 连续网络或 5xx 错误阈值 |
| failure_cooldown_seconds | 300 | 连续错误后的冷却 |

`download_state` 默认指向项目 `data/download_guard.json`，与具体数据库路径无关。冷却、最近请求时间和分组计数持久保存，因此切换数据库或重启内核不会绕过保护。服务器给出的更长 `Retry-After` 优先。冷却期间运行更新会直接报告暂停，不再访问行情服务。不要删除状态文件来反复重试。

YahooProvider 复用一个 Session 和有限数量的 Ticker 对象；现有 SQLite 行情缓存仍是减少请求的主要手段。yfinance 自身持久缓存时区和 cookie，并不等于缓存全部行情：https://ranaroussi.github.io/yfinance/advanced/caching.html 。

预算与间隔在 Session.request 入口统计，底层自动重定向可能额外往返。Nasdaq 股票目录每天最多正常刷新一次，其请求不计入 Yahoo 预算。免费服务没有承诺固定安全配额，因此无法保证永不被限制。首次全市场初始化可能多轮完成，完成一个区间就提交一次，之后只补缺。

同步报告新增 `paused`、`pause_reason`、`resume_after`（UTC）和 `network_requests`。暂停保留已提交区间，不把剩余任务标为成功，也不继续请求后续股票；等到允许时间再执行同一更新即可。CLI 暂停退出码为 2。修改代码后，已打开的 Notebook 需要 Restart 内核，再从第一格运行以加载保护逻辑。

## 数据库与内存

数据库默认为 `data/market.sqlite3`，包含 instruments、universe_snapshots、security_snapshots、bars、corporate_actions、sync_state、scan_runs、scan_results 和 repairs。K 线主键为 `(symbol,timeframe,ts)`，另有 `(symbol,timeframe,session_date,ts)` 索引。

日线时间戳为该交易日收盘 UTC 时间；分钟线是开盘 UTC 时间。session_date 为纽约交易日期，session 区分 pre/regular/post。交易日历采用 XNYS（美股常规时段共同日历），默认收盘后 30 分钟才纳入扫描。含盘前盘后的分钟会在当日纽约 20:00 加宽限时间前标记 provisional。

初始化后先看同步状态，只拉缺失日期，并合并相邻缺失交易日。网络返回空值时记录 no_data，之后允许重试。已有完整日期不反复下载；Yahoo 普通历史修订不会在无新请求时自动发现，可以使用 `repair=True` 定向修复。

全市场证券目录占用少量内存；行情按单股限制条数读取。配置 batch_size 控制处理批次；没有全市场分钟 DataFrame。SQLite WAL 允许读写并行，FileLock 防止两个更新器同时写库；每个下载区间的 K 线和同步状态在同一事务中提交。中断前已完成区间会保留。

## 历史限制与公司行动

请求默认日线 730、15m/5m 30、1m 7 个自然日。实现按当前 Yahoo 约束将 5m/15m 远端补缺范围限制在最近 60 天内，1m 在最近 30 天内拆成至多七天的请求；实际可用范围可能更短，错误会保留在同步报告。数据库旧记录不受远端窗口影响。

使用 `auto_adjust=False`、`back_adjust=False`、`repair=False`。Yahoo 返回价格本身通常已经拆股调整；“不自动复权”不代表交易发生时的原始名义价格。不启用股息总回报复权；不混用 Adj Close 计算成交额。保存拆股、股息和口径标签。

增量请求发现新拆股时，对该股票受影响的旧数据标为待修复，重新获取可用历史。日线修复覆盖已有历史；远端保留期之外的分钟历史保留 stale_before_split 标记，不能冒充统一价格基准。修复失败不推进成功状态。首次无新数据请求时不会主动发现尚未发布的公司行动。

市值、行业按真实获取时间保存。最近已收盘日扫描可使用当前资料快照并标明时间；历史日期只取截止收盘前已保存的快照。免费接口不提供足够的历史市值时，显示 missing_point_in_time_metadata，不能将当前市值倒填到历史中。带有 session_asof 标记且仍对应最近收盘交易日的快照可跨周末/休市复用；其余快照超过 TTL 后显示 stale_metadata，运行更新可刷新。

## 结果状态

- passed：所需数据完整，且所有配置条件满足。
- failed：数据足够，至少一项条件不满足。
- insufficient：过期日线、未完成 K 线、缺少预热、市值或行情缺口等；reasons 和 check_* 列解释具体原因。

查看只读健检：`selectstock check`。每次扫描记录配置、执行的扫描器、公式版本、截止日、证券资料时间及各状态计数。首版不包含后台调度、自动下单、收益回测或精确 TradingView 结果保证。
