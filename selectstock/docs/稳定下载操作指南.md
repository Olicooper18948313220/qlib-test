# 稳定下载操作指南（v0.2.0）

本次修复保留全部合格股票的可用历史，Leader 和 Potent 共用日线，Premarket 由用户在 TradingView 操作。

## 运行步骤

1. 停止旧下载并点击 Notebook 顶部 **Restart**，重启 py311 内核。
2. 从第一格开始运行。应显示 `selectstock 0.2.0`、代码指纹和 Python 路径；若提示旧模块，必须重启内核。
3. 参数区保留 `DEMO=False`、`SYMBOLS=[]`、一年日线 `HISTORY_DAYS["1d"]=365`，两个扫描器启用。日线更新设 True，分钟更新设 False。
4. 运行“单独更新日线”格。进度显示当前阶段、股票、已处理/总数量、缓存、跳过、异常、请求量、耗时和预计剩余时间。
5. 普通 600 次请求预算会自动休息 60 秒继续。429/403 遵守至少 15 分钟及更长 Retry-After；网络连续失败冷却五分钟。连续三次恢复仍失败才暂停。等待时可按停止，之后同配置运行可续传。
6. 完成后检查报告和异常清单，再将更新设 False、重跑参数格，分别运行两个扫描器及导出。不要在首次全量下载期间反复点击 Run All。

`configs/data.yaml` 默认 `auto_resume: true`、`max_recovery_attempts: 3`。可以关闭自动恢复做调试；无需为提速增加并发。`max_requests_per_run` 为每段请求预算，不是整个下载任务的上限。请求数包含行情接口内部资料、cookie 等调用。

## 跳过与复查

- 新股只请求首次交易日之后的可用历史。Leader 所需窗口齐全时可扫描；Potent 默认不足 250 个交易日则跳过。
- 当前目录之外的股票停止日常更新与当前扫描；保留本地历史。目录重新出现时恢复。目录消失或 Yahoo “possibly delisted” 文本都不等于已确认退市。
- 普通空缺当天不反复请求，下一交易日再复查；坏行默认等待 24 小时。连续三个不同已收盘交易日仍异常，延后七天。新的交易日行情可独立更新，不受旧缺口等待影响。
- 完全相同的重复行情去重；冲突时间戳、非有限数值、非正价格、负成交量、OHLC 关系错误逐行隔离。不会填零或补造价格。
- 其余有效数据继续保存，已有有效本地行不被坏返回覆盖。拆股基准修复保持严格校验；修复失败时不提交混合价格基准。
- 坏行或缺口处在某扫描器的所需窗口时，该扫描器跳过该股票；窗口之外的旧缺口不影响 Leader。跳过不是满足筛选条件，也不等于全市场下载失败。

## 结果与故障检查

报告 `status` 为 completed、partial、paused、stopped 或 offline。`processed/total` 表示股票及周期任务的处理进度，downloaded 是下载区间数，rows 是写入条数；处理完成不代表每支股票数据完整。

`segments` 是执行分段数，`recoveries` 是真实故障恢复次数，`skipped` 是下载暂缓/目录外任务数，`quarantined_rows` 是隔离坏行数，`asof` 是冻结的截止交易日。中断后继续同一任务时统计累计保留；新的一轮完成后再次执行则重新统计。

数据库 `bar_quarantine` 保存坏行原始字段、日期、原因；`retry_days` 保存下一次复查时间。导出诊断 CSV 显示 passed、failed、skipped；旧记录的 insufficient 仍可读取。任务状态保存在 sync_jobs/job_context，缓存和断点不依赖 Notebook 输出。

同配置续传冻结原股票池和截止日期，避免跨日时混淆任务。任务结束后再次更新会取得新的截止日和目录。旧任务的历史截止日不使用后来获取的当前市值冒充历史资料。

首次 schema v2 升级自动创建数据库 `.before_v2.bak`；本次另有 `data/backups/` 备份。备份、数据库、日志与运行结果均不提交 Git。实际工作 Notebook 保留用户参数和输出，Git 提交版本保留演示默认参数并清除输出。
