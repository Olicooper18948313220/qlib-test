# V1 修复版：使用与验收

## 如何操作

1. 在资源管理器打开项目目录，双击 scripts/start_web.bat。启动器会检查 Python 3.11/3.12 和依赖，打开本机网页；如果 8501 已被占用，会自动选择 8502 至 8521 中的空闲端口并打印实际地址；失败时保留错误信息。
2. 首页点击“检查数据”。任务使用只读数据库连接，进度与错误记录在首页；取消操作会在数据库查询或计算检查点退出。
3. “新建回测”先设短区间、固定股票子集。股票按代码排序选择，此子集只用于功能验证。
4. 设置持仓数、费用、调仓日、信号开关与两个放量阈值，点击启动。再次提交时已有任务会被拦截。
5. 可以刷新或关闭网页；重新打开首页，任务状态会从磁盘恢复。工作进程意外退出显示失败，不会一直显示运行中。
6. 在“结果与实验”查看新实验，展开交易记录、每日持仓、跳过订单。选择两次实验对照参数差异，下载完整 ZIP。

首页会每 2 秒刷新任务面板。默认回测按指定星期生成信号，下一市场交易日开盘执行；如果该星期当天休市，本周不另补调仓。调仓交易后先按有效收盘价估值，无有效收盘价则保留最近已知价格并标记陈旧估值。

## 结果目录

- 网页：runs/jobs/<任务编号>/result。
- 命令行：--output 指定的目录；同名目录已存在时，创建新后缀目录，失败实验也不覆盖。
- summary.json：绩效摘要；equity_curve.csv：每日现金、持仓市值、总资产。
- trades.csv：逐笔数量、原始开盘价、滑点后成交价、佣金、税和滑点成本。
- positions.csv：逐日逐股数量、估值价格、最近价格日期及陈旧标记。
- skipped_orders.csv：未成交原因；零交易也生成带表头 CSV。
- run_metadata.json：实际生效配置、数据概况、股票子集、预热记录、代码摘要、引擎版本。
- status.json / execution.log / error.log：任务状态、进度和错误；后台另有 process.log。

历史结果保留原文件。页面标出旧版或未验收版本；full、smoke、v1_smoke、v1_smoke2 属于含已知账本缺陷的旧结果，不用于当前策略结论。

## 配置与编辑

网页表单只修改本次实验；更改默认值请编辑 configs。组合参数来自 portfolio.yaml，回测日期来自 backtest.yaml，信号来自 signals.yaml；本次表单或 CLI 参数覆盖这些默认值。

提交时冻结完整参数，后台运行不会重新读取被用户随后更改的默认配置。生效日期、数据库路径和股票数也写入快照。未知策略版本及不支持的组合模式会报错，尚未实现的信号阈值和因子表达式会提示。

CLI 例子：

```powershell
cd D:\qlib_quant
$env:PYTHONPATH = "$PWD\src"
& 'D:\Anoconda3\envs\py311\python.exe' -m qlib_quant.cli backtest --start 2020-01-01 --end 2020-02-28 --max-stocks 5 --max-positions 3
```

也可以传 --config 自定义覆盖 YAML（顶层为 data、backtest、signals、factors）。保留 validate、export 和 qlib-export 命令。

## 验收范围

本轮验收针对账本正确性和本地工作台操作闭环。覆盖手工可核算的买卖与费用、持仓增减、无效价格拒绝成交、已知停牌、陈旧估值、空交易、信号分组与因果性、重复运行、只读数据库、任务并发/取消/退出恢复，以及网页报告和参数对比。

真实数据库的交易状态大面积缺失，后复权价格仍用于研究成交，涨跌停、公司行动现金流及真实交易可达性未完成建模。V1 通过功能验收不等于全市场策略有效，也不等于可直接用于实盘。
